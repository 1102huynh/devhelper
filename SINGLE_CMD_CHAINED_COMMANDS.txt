  ✅ Dùng && để chain commands

🔧 IMPLEMENTATION

KEY CHANGES:
────────────────────────────────────────────────────────────────────────

OLD Approach (Multiple CMD Windows):
```typescript
for (let i = 0; i < suites.length; i++) {
    // Build command for suite
    const command = buildCommand(suite[i])

    // Open separate CMD window for EACH suite
    await fetch(`${API_BASE}/test/run`, {
        body: JSON.stringify({
            command: command,
            openTerminal: true  // Opens NEW window
        })
    })

    await delay(500)  // Delay between windows
}
// Result: 3 suites = 3 CMD windows opened
```

NEW Approach (Single CMD Window):
```typescript
const commands: string[] = []

// Collect all commands first
for (let i = 0; i < suites.length; i++) {
    const command = buildCommand(suite[i])
    commands.push(command)
}

// Chain all commands with &&
const chainedCommand = commands.join(' && ')
// Example: "cmd1 && cmd2 && cmd3"

// Open ONE CMD window with chained command
await fetch(`${API_BASE}/test/run`, {
    body: JSON.stringify({
        command: chainedCommand,  // All commands in one
        openTerminal: true        // Opens ONE window
    })
})
// Result: 3 suites = 1 CMD window, runs sequentially
```

💡 && OPERATOR BEHAVIOR
═══════════════════════════════════════════════════════════════════════════

The && operator in CMD/Shell:
  → Runs commands sequentially
  → Waits for each command to complete
  → If a command fails (exit code != 0), stops execution

Example 1: All Success
  cmd1 && cmd2 && cmd3
  → cmd1 runs → SUCCESS → cmd2 runs → SUCCESS → cmd3 runs → SUCCESS

Example 2: One Failure
  cmd1 && cmd2 && cmd3
  → cmd1 runs → SUCCESS → cmd2 runs → FAILURE → cmd3 SKIPPED

This is GOOD for test suites because:
  ✓ If build fails, don't waste time running tests
  ✓ Clear indication of where failure occurred
  ✓ Prevent cascading failures

Alternative: Use ; instead of &&
  cmd1 ; cmd2 ; cmd3
  → Runs ALL commands regardless of failures
  → May be preferred in some scenarios

Current Implementation: Uses &&
  → Safer approach
  → Stops on first failure
  → Can be changed to ; if needed

⚠️ CONSIDERATIONS
═══════════════════════════════════════════════════════════════════════════

1. Command Length Limit
   ────────────────────────────────────────────────────────────────────
   Windows CMD has ~8192 character limit for command line

   Solution:
   → Most test suites won't hit this limit
   → If needed, can batch into groups
   → Or use a script file instead

2. Failure Behavior with &&
   ────────────────────────────────────────────────────────────────────
   && stops on first failure

   Solution:
   → This is actually desired behavior for tests
   → If need to run all regardless, change to ; separator
   → User can see which suite caused stop

3. No Parallel Execution
   ────────────────────────────────────────────────────────────────────
   All suites run sequentially, not parallel

   Solution:
   → This is by design for stability
   → Parallel can cause resource conflicts
   → If parallel needed, use multiple CMD approach

4. Can't Stop Individual Suite
   ────────────────────────────────────────────────────────────────────
   Ctrl+C stops all remaining suites

   Solution:
   → This is expected behavior with chained commands
   → User stops entire test session
   → Can still review logs of completed suites
